TL;DR

Truncated backpropagation through time (BPTT) trains only the last \(B\) of \(T\) loops of a looped transformer to save compute. We fit one scaling law over model size, data and both loop counts, in which loops add effective parameters and truncation discounts them. Its answer to the title: truncate only when the number of forward loops is fixed in advance. When both loop counts can be chosen, use full BPTT through fewer loops.

Abstract

Looped transformers reuse a shared block of layers to increase computational depth without increasing the number of trainable parameters. Training uses backpropagation through time (BPTT), either through all loops or through only the last part of the recurrence. Truncating backpropagation saves training compute and activation memory, but can reduce the gains from looping. Across nearly 600 training runs spanning over three orders of magnitude in training tokens per parameter, we study how model size, training tokens, and forward and backward loop counts jointly determine loss, and fit a unified scaling law that captures the effects of looping and truncation through effective parameters. Despite the training-compute savings of truncation, our fitted law favors full BPTT when forward and backward loop counts are jointly optimized. In matched-compute comparisons spanning 58M–919M non-embedding parameters and up to 300 training tokens per parameter, full BPTT through fewer loops consistently outperforms truncated settings of the same compute. Using this law, we further show that at fixed model size, compute-optimal training increases both the loop count and the training-token budget as compute grows. When model size is also free, the law identifies two fully trained loops as the best looped setting. Experimentally, this setting achieves lower loss than the compute-optimal non-looped model with about 27% fewer non-embedding parameters and only 8% more training compute.

Four takeaways

Takeaway 1

Loops add effective parameters; truncation discounts them

We measure what looping is worth by an effective parameter count: the size of a non-looped model that reaches the same loss on the same tokens. Only the recurrent block \(N_{\mathrm{rec}}\) runs in every loop; the prelude and coda \(N_{\mathrm{once}}\) run once.

Each fully trained loop enlarges the effective size of the recurrent block, with diminishing returns toward a finite ceiling. Truncation discounts this gain, and doubling \(B\) adds more effective parameters than doubling \(T\) alone.

\[N_{\mathrm{eff}} = N_{\mathrm{once}} + g(T,B)\,N_{\mathrm{rec}}\] \[g(T,B) = \exp\!\big[c\,\big(1 - T^{-p}B^{-q}\big)\big]\]

\(q \approx 1.02 \gg p \approx 0.24\): a backward loop is worth far more than a forward loop.

  • (4, 4) worth 1.76× the parameters
  • (4, 1) worth only 1.19×
Takeaway 2

Truncate only when the forward-loop count is prescribed

A forward pass through the recurrent block costs one unit of compute and a backward pass two, so a loop setting \((T,B)\) costs \(T+2B\) units per token: \((8,2)\) and \((4,4)\) cost the same. Whether truncation pays depends on what is held fixed.

Takeaway 3

At fixed size, spend additional compute mostly on training tokens

When a model must fit a memory budget, extra compute can buy more loops per token or more training tokens. Under the fitted law, the optimal fully trained loop count grows as \(C^{0.24}\) and the token count as \(C^{0.76}\).

Loop counts are integers, so the best setting changes in steps: no looping, then two, then four trained loops. Between steps, added compute goes to tokens. In the runs, the best fully trained setting beats the best truncated one at every size and compute.

Takeaway 4

Two fully trained loops are competitive with fewer parameters

When model size is free, compute spent repeating a block could instead train more unique parameters, so the law favors no looping. The best looped setting is \((2,2)\): \(g(2,2)\approx1.91\), so two shared loops are worth almost two untied copies of the block.

At equal compute, \((2,2)\) comes within 0.001–0.008 nats of the compute-optimal non-looped model across three budgets while having 27–32% fewer non-embedding parameters. At the largest budget, 8% more compute is enough for it to reach the lower loss.

One law for size, data and loops

The validation loss follows a coupled size–data law in which the model size is replaced by the effective size. The looping coefficient adds three coefficients \(c,p,q\) to the six of the size–data law; all nine are fitted jointly on 230 configurations.

\[L(N,D,T,B) \;=\; E + \left[A\left(\frac{N_{\mathrm{eff}}}{N_0}\right)^{-\alpha} + H\left(\frac{D}{D_0}\right)^{-\beta}\right]^{\kappa}\] \[N_{\mathrm{eff}} = N_{\mathrm{once}} + g(T,B)\,N_{\mathrm{rec}}, \qquad g(T,B) = \exp\!\big[c\,\big(1 - T^{-p}B^{-q}\big)\big]\]
Normalization \(g(1,1)=1\)

A single loop recovers the non-looped model.

Monotonicity \(\partial_T g>0,\ \partial_B g>0\)

More loops of either kind raise the coefficient.

Zero-backward boundary \(g(T,0)=0\)

An untrained recurrent block adds no effective size.

Saturation \(g\le e^{c}\approx3.04\)

Finite parameters store finite information.

Code

The release contains the looped transformer in plain PyTorch, its Megatron-LM trainer with truncated BPTT, the data preparation, the held-out evaluation and the compute accounting. The README lists the data preparation steps; scripts/model_sizes.py prints the settings of every token budget. 

git clone https://github.com/xjxyys/Truncate-or-Not.git && cd Truncate-or-Not
pip install -e '.[monitoring,dev]'
# Megatron-LM is used as a source checkout next to this repository
git clone https://github.com/NVIDIA/Megatron-LM.git ../Megatron-LM
git -C ../Megatron-LM checkout ed6ac270ba

# 240M, (T, B) = (4, 4), 4 x 2^30 tokens, 8 GPUs
python scripts/train.py --run-name m240_d4_t4b4 --size 240M --loops 4 --backprop-loops 4 --tokens 4

# held-out evaluation
echo m240_d4_t4b4 > runs.txt
python scripts/eval_heldout.py eval --list runs.txt --gpus 8
python scripts/eval_heldout.py read --list runs.txt

For truncated BPTT, lower --backprop-loops, e.g. --backprop-loops 1 for \((4,1)\).
